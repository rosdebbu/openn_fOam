1. Introduction & Research Objectives

Aerothermal fluid dynamics analysis is essential across mechanical, aerospace, civil, and data-center thermal engineering. However, industry workflows rely on established desktop software suites (e.g., ANSYS Fluent, COMSOL Multiphysics, Star-CCM+) or complex command-line toolchains (e.g., OpenFOAM). These tools require extensive installation overhead, high licensing fees, and decoupled offline post-processing in ParaView.

Core Research Objectives for UR2627GEN317:

  1. Indigenous Numerical Solver Engine: Implement an in-memory 3D incompressible Navier-Stokes solver incorporating the Boussinesq thermal buoyancy formulation.
  2. Instant Physics-Informed Surrogate: Develop a sub-50 ms physics-informed neural surrogate model for real-time exploratory fluid design.
  3. Bare-Metal Hybrid Compute: Implement a zero-copy FFI bridge between Python and Rust (via PyO3/Maturin) to leverage multi-threaded SIMD stencils and bypass Python's Global Interpreter Lock (GIL).
  4. Web-Native 3D Telemetry: Construct an interactive Three.js/WebGL client with bi-directional WebSocket streaming for live residual tracking and dynamic cross-sectional field slicing.
  5. Two-Way OpenFOAM / ParaView Interoperability: Provide automated case compilation to ensure industrial-grade validation and continuity.

2. Comprehensive Literature Review

2.1 Classical Numerical CFD & Fractional-Step Formulations

The cornerstone of incompressible flow simulation is the fractional-step projection method originally introduced by Chorin (1968). By decoupling momentum advection and diffusion from the incompressibility constraint, the velocity field is advanced to an intermediate state ($\vec{u}^*$), followed by a scalar Pressure-Poisson equation to enforce a divergence-free condition:

$$\vec{u}^* = \vec{u}^n + \Delta t \left[ \nu \nabla^2 \vec{u}^n - (\vec{u}^n \cdot \nabla) \vec{u}^n + \vec{g} \beta (T^n - T_{\text{amb}}) \right]$$
$$\nabla^2 p = \frac{\rho}{\Delta t} \nabla \cdot \vec{u}^* \quad \Longrightarrow \quad \vec{u}^{n+1} = \vec{u}^* - \Delta t \nabla p$$

Jasak (1996) and Weller et al. (1998) demonstrated that in finite-volume frameworks like OpenFOAM, co-located grids require Rhie-Chow interpolation to eliminate odd-even pressure decoupling. For aerothermal flows where density variations are primarily driven by moderate temperature differentials, the Boussinesq approximation (Tritton, 1988) provides exceptional fidelity without the stiff numerical penalties of fully compressible equations.

2.2 Physics-Informed Surrogates & Deep Learning for Fluid Dynamics

Recent literature reveals a paradigm shift toward AI-assisted fluid simulation. Raissi, Perdikaris, and Karniadakis (2019) pioneered Physics-Informed Neural Networks (PINNs), embedding PDE residuals directly into network loss functions:

$$\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{data}} + \lambda_{\text{NS}} \|\nabla \cdot \vec{u}\|^2 + \lambda_{\text{mom}} \|\partial_t \vec{u} + (\vec{u}\cdot\nabla)\vec{u} + \nabla p - \nu \nabla^2 \vec{u}\|^2$$

Concurrently, Li et al. (2020) introduced Fourier Neural Operators (FNO), enabling zero-shot super-resolution and mesh-invariant mapping between boundary parameters and continuous flow fields. Brunton et al. (2020) emphasized in their definitive survey that AI models do not displace numerical solvers; rather, they serve as ultra-fast (<50 ms) parametric surrogates, creating a compelling case for a dual-mode hybrid architecture.

2.3 Systems-Level Acceleration: Rust vs. Python/C++ in Scientific Computing

While Python dominates AI and data analysis, its Global Interpreter Lock (GIL) and dynamic type overhead create severe bottlenecks in tight numerical stencil loops. Traditionally, developers have turned to C++ with OpenMP or MPI. However, modern systems research highlights Rust (Matsakis & Klock, 2014) as an optimal alternative offering memory safety without garbage collection, compiler-enforced thread-concurrency, and auto-vectorizing SIMD intrinsics. The PyO3 native extension bridge enables zero-copy shared memory access with NumPy array buffers, establishing an ideal hybrid compute paradigm.

2.4 Real-Time Web Telemetry & In-Browser Scientific Visualization

Historically, scientific visualization required local installations of heavy desktop clients like ParaView or VisIt. Advances in WebGL 2.0, WebGPU, and Three.js (Cabello et al., 2024) have enabled real-time hardware-accelerated 3D rendering directly within web viewports. Coupled with binary WebSocket protocols (RFC 6455), simulation telemetry—including convergence residuals and velocity/pressure fields—can be streamed dynamically to the client with sub-16 ms frame delivery.

4. Formal Scope & System Boundary Definition

4.1 In-Scope Deliverables

  • Physical Governing Equations: Incompressible 3D Navier-Stokes coupled with Boussinesq thermal buoyancy and advection-diffusion temperature transport.
  • Spatial & Temporal Discretization: Structured Cartesian grid ($N_x \times N_y \times N_z$), 1st-order upwind differencing for convective stability, 2nd-order central differencing for viscous/thermal diffusion, and explicit Euler/Adams-Bashforth time stepping adhering to the Courant-Friedrichs-Lewy (CFL) stability criterion: $$\Delta t \le \min \left( \frac{\Delta x}{|u|_{\max}}, \frac{\Delta x^2}{2\nu} \right)$$
  • Pressure-Poisson Solver: Iterative sparse linear system solver utilizing SciPy sparse conjugate gradients and multi-threaded Rust Gauss-Seidel kernels.
  • Surrogate Engine: Physics-informed analytical and deep-learning surrogate for instant steady-state wake, stagnation, and thermal plume prediction.
  • Web Telemetry: Full-duplex WebSocket streaming (30–60 FPS), live logarithmic residual chart (Chart.js), dual 2D/3D visualizers, and parametric slider steering.
  • Industrial Validation Export: Automated generation of valid `0/`, `constant/`, and `system/` case dictionaries for `buoyantBoussinesqSimpleFoam` and `.vtk` structured points.

4.2 Out-of-Scope (Boundaries for Current Phase)

  • Compressible, transonic, or supersonic shock-wave capturing regimes ($Ma > 0.3$).
  • Multiphase flows involving free-surface interface tracking (e.g., Volume of Fluid / Level Set methods).
  • Complex body-fitted unstructured tetrahedral meshing inside the web client (structured Cartesian voxelization is employed for real-time performance).
